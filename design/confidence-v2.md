---

## 一、V1 体系的问题

| 问题 | 根因 |
|------|------|
| "说得多=分数高" | specificityScore 按字数和标记词数加分，纯情绪宣泄"我好烦啊真的好烦啊"也能拿高分 |
| 关键词命中≠信息充分 | 关键词2命中=2分，但"焦虑"俩字=1分 vs "压力大到失眠脑子里转不完"也才2个关键词=2分 |
| 域匹配质量是"加分项"不是"筛选器" | 用户说"课题分离"但域是拖延，bookScore 照样加分，实际应该给域推荐 |
| 阈值拍脑袋 | ≥5 / 1.5~5 / <1.5，不同域天然分不一样 |
| 维度交叉加分 | domainScore + bookScore + specificityScore 权重混加，无法解释"为什么这个输入被判高置信" |

---

## 二、置信度的本质

**置信度 = AI 能多准确地理解这个用户当前的真实困扰。**

它不取决于用户说了多少字，而取决于用户给出了多少**"可诊断"的有效信息维度**。

一个完整可诊断的输入应该包含：

| 维度 | 含义 | 典型例子 |
|------|------|---------|
| 事件锚点 | 具体发生了什么事 | "改设计改到凌晨"、"面试紧张"、"离职8个月" |
| 情绪标签 | 伴随什么感受 | "焦虑"、"沮丧"、"麻木"、"后悔"、"纠结" |
| 行为事实 | 他反复做了什么/没做什么 | "每次都改到停不下来"、"不敢开口"、"刷手机不想动" |
| 时间线索 | 从什么时候开始的 | "从小就这样"、"上一份工作之后"、"已经半年了" |
| 因果推测 | 他自己猜的原因 | "怕被看不起"、"怕稿子交出去被骂"、"其实不想进那个系统" |
| 目标期待 | 他想要什么变化 | "想改但改不掉"、"想找工作但动不了" |

## 三、五维度打分体系

### 3.1 维度定义与 Rubric

共 5 个独立维度，每个 0-3 分，**总分 0-15**。每个维度独立打分、不交叉加分。

#### ① 事件锚点 (anchor) — 有具体事吗？

| 分 | 含义 | 输入示例 |
|----|------|---------|
| 0 | 没说具体事 | "好烦啊"、"最近不太行" |
| 1 | 说的事太笼统 | "工作压力大"、"我有拖延" |
| 2 | 有具体场景/事件 | "改设计改到凌晨"、"面试紧张说不出话" |
| 3 | 具体场景 + 频次/时间/对象 | "改设计改到凌晨，已经连续三周了"、"每次跟男朋友吵架都控制不住情绪" |

#### ② 情绪明确度 (emotion) — 感受清晰吗？

| 分 | 含义 | 输入示例 |
|----|------|---------|
| 0 | 没提感受 | "改设计改到凌晨" |
| 1 | 只有情绪词无体感描述 | "我好焦虑"、"我好烦" |
| 2 | 情绪词 + 体感/行为描述 | "焦虑到失眠"、"明明不累但就是紧张" |
| 3 | 有矛盾/复杂情绪 或 情绪 + 触发点 | "每次改稿到三点就焦虑，怕交出去被骂"、"想开始但又觉得没意思" |

#### ③ 行为可观察 (behavior) — 说了什么具体行为？

| 分 | 含义 | 输入示例 |
|----|------|---------|
| 0 | 没说行为 | "我压力好大" |
| 1 | 说行为但无频率/程度 | "我改稿改很久"、"我拖延" |
| 2 | 说行为 + 频率/程度 | "每次改稿都停不下来"、"已经三个月没动了" |
| 3 | 行为 + 频率 + 自我观察/内心活动 | "每次改稿都停不下来，明知道可以睡了但手放不开" |

#### ④ 时间/因果线索 (context) — 有背景吗？

| 分 | 含义 | 输入示例 |
|----|------|---------|
| 0 | 没提时间/原因 | "我好焦虑" |
| 1 | 提了大概时间 | "最近这样"、"从上个月开始" |
| 2 | 有因果推测（用户自己的猜测） | "可能是怕稿子不够完美"、"因为上次被领导骂过" |
| 3 | 因果 + 对比/深层 | "以前不会这样，自从上次被领导骂过之后就开始了"、"上一份工作太累了不想再进那种系统" |

#### ⑤ 域匹配质量 (domainMatch) — 在当前域里信息量如何？

| 分 | 含义 | 检测方法 |
|----|------|---------|
| 0 | 关键词命中 ≤ 1 个 | `calcDomainScore(text, domainKey).matched.length <= 1` |
| 1 | 关键词命中 2-3 个 | 纯关键词命中，无正则/书籍 |
| 2 | 有正则/复合模式命中 | 命中 `改.*停不下来` 等 regex pattern |
| 3 | 有书籍概念 或 多域信号一致 | 命中 `BOOK_CONCEPTS` 中的概念（课题分离、完美主义等） |

### 3.2 特殊规则

| 规则 | 处理 |
|------|------|
| **纯情绪宣泄** | 如果 anchor=0 + emotion≤1 + 但有大量情绪词（"好烦好烦好烦"、"焦虑焦虑焦虑"）→ 强制打 L1，直接走 Step1 纯共情 |
| **多轮历史补分** | 每经过一轮对话（history.length ≥ 4/8/12），context 维度 +1（0→1→2→3），因为聊了几轮自然带出了时间/因果线索 |
| **域不匹配降级** | 如果 domainMatch ≥ 2 但其他域的 score 显著更高（≥ 自身 2 倍）→ 返回 `deviation.signal`，前端给域推荐提示 |
| **快捷标签** | 点击预设快捷标签 → 直接 L4（标签本身就是为当前域设计的，用户明确表达了意图） |

## 四、总分 → 等级 → 工作流策略

### 4.1 映射表

| 总分区间 | 等级 | 含义 | chatStep=1 时调 AI 的 step | AI 输出内容 | chatStep 推进 |
|---------|------|------|--------------------------|-------------|--------------|
| **12-15** | **L4 高** | 信息充分，可精准开方 | `step=3`（直接开方） | 深度共情点破 + 双书处方 + 金句 + 追问 | chatStep→4（跟进闭环） |
| **8-11** | **L3 中高** | 有方向但深层动机未明 | `step=2`（推测+深挖） | 承接 + "可能是...甚至可能是..." 推测性排比 + 3个追问 + 安全感结尾 | chatStep→3（下轮开方） |
| **4-7** | **L2 中低** | 有个模糊方向但缺细节 | `step=1`（完整聊） | 高质量共情（带比喻）+ "先聊再给建议"表态 + 2-3个追问 + 安全感结尾 | chatStep→2（下轮挖） |
| **0-3** | **L1 低** | 纯情绪宣泄或几乎没说 | `step=1`（纯共情+引导） | 共情（带比喻）+ 引导说出来的追问 | chatStep→2 |

### 4.2 流程图

```
用户输入
  │
  ├─ 快捷标签？ → YES → L4, step=3
  │
  └─ NO → 计算五维度得分 → 总分 0-15
          │
          ├─ 纯情绪宣泄？ → YES → L1, step=1
          │
          ├─ L4 (12-15) → step=3 → 开双书处方 → chatStep=4
          ├─ L3 (8-11)  → step=2 → 推测深挖   → chatStep=3 → 下轮 step=3
          ├─ L2 (4-7)   → step=1 → 完整聊天   → chatStep=2 → 下轮 step=2/3
          └─ L1 (0-3)   → step=1 → 共情引导   → chatStep=2 → 下轮 step=2/3
```

### 4.3 跟进循环

进入 chatStep=4 之后：用户任何输入 → 都调 step=4（跟进闭环），主动回顾之前建议的执行情况，保持知心姐姐聊天感。

## 七、实现架构

```
calcConfidenceV2(text, domainKey, quickTag=false, historyCount=0)
  │
  ├─ Step 1: 快捷标签检测 → L4, score=15, return
  │
  ├─ Step 2: 五维度独立打分
  │   ├─ scoreAnchor(text)     → 0-3
  │   ├─ scoreEmotion(text)    → 0-3
  │   ├─ scoreBehavior(text)   → 0-3
  │   ├─ scoreContext(text, historyCount) → 0-3
  │   └─ scoreDomainMatch(text, domainKey) → 0-3
  │
  ├─ Step 3: 特殊规则
  │   ├─ 纯情绪宣泄检测 → anchor=0 + emotion≤1 + 大量情绪词 → 强制 L1
  │   ├─ 多轮历史补分 → historyCount≥4 → context+1
  │   └─ 域不匹配检测 → 其他域 score ≥ 2× current → deviation signal
  │
  ├─ Step 4: 总分 → 等级映射
  │   ├─ 12-15 → L4
  │   ├─ 8-11  → L3
  │   ├─ 4-7   → L2
  │   └─ 0-3   → L1
  │
  └─ return { score, level, label, dimensionScores, deviation, isEmotionalOnly }
```

## 九、与后端的关系

前端 V2 评分决定调后端 prompt step (1/2/3)。后端 ask.js prompt 本身不需要改——前端选对 step，后端 prompt 里的 Step1/2/3 会按设计的风格输出。

后端 response 可以加 `confidenceSuggestion` 字段（可选），但主要决策逻辑在前端。
